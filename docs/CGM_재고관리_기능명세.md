# CGM 재고관리 기능명세

## 1. 목적

CGM 센서 재고를 센서 종류별로 관리하고, **유효기간**과 **개봉 후 사용기간**을 함께 기준으로 삼아 먼저 만료되는 재고부터 사용하도록 돕는다.

이 문서의 목표는 단순 재고 수량 관리가 아니라, **폐기 손실을 줄이고 사용 우선순위를 명확히 하는 운영 기준**을 정의하는 것이다.

## 2. 범위

### 포함
- 센서 종류 등록 및 관리
- 재고 개별 등록
- 유효기간 관리
- 개봉일 관리
- 상태 계산 및 우선순위 정렬
- 만료 임박 알림 기준
- 사용 시작, 사용 종료, 폐기 처리
- 백업 및 복원

### 제외
- 서버 연동
- 다중 사용자 권한
- 외부 병원 시스템 연동
- 구매 발주 자동화

## 3. 핵심 원칙

1. 각 센서는 **개별 재고 항목**으로 관리한다.
2. 재고의 사용 우선순위는 **실효 종료일**이 가장 빠른 순서로 정한다.
3. 실효 종료일은 아래 두 날짜 중 더 이른 날짜를 사용한다.
   - 센서 자체 유효기간
   - 개봉 후 사용기간 종료일
4. 사용중 센서와 미개봉 센서는 상태를 분리해서 보여준다.
5. 모든 경고는 오늘 날짜를 기준으로 계산한다.

## 4. 사용자 목표

- 지금 써야 할 센서를 한눈에 확인한다.
- 곧 만료될 센서를 미리 파악한다.
- 센서 종류별 재고 분포를 확인한다.
- 개봉 후 사용기간을 넘긴 센서를 놓치지 않는다.
- 오래 남은 재고보다 먼저 버려질 재고를 우선 사용한다.

## 5. 화면 구성

### 5.1 대시보드

대시보드는 앱 진입 시 가장 먼저 보이는 화면이다.

- 센서 종류별 재고 수량
- 우선 사용 대상 목록
- 경고 배지

#### 주요 동작
- 재고 상세 진입
- 재고 추가 화면 이동
- 상태 필터 진입

### 5.2 재고 목록

재고를 센서 종류별, 상태별로 탐색하는 화면이다.

#### 필터
- 센서 종류
- 상태

  - 사용중
  - 곧만료
  - 만료
  - 폐기

#### 정렬
- 실효 종료일 오름차순
- 개봉일 오름차순
- 등록일 최신순

#### 카드 표시 항목
- 센서 종류명
- LOT
- 유효기간
- 개봉일
- 실효 종료일
- 상태

### 5.3 재고 등록 / 수정

센서 개별 항목을 생성하거나 수정하는 화면이다.

#### 입력 필드

## 6. 데이터 구조

```javascript
{
  sensorTypes: [
    {
      id: "careSens_air",
      name: "CareSens Air",
      wearDays: 15,
      color: "#00c6fb",
      gtin: "08809126640655",
      model: "CGM-ST-002"
    }
  ],
  inventory: [
    {
      id: "inv_001",
      typeId: "careSens_air",
      lot: "250701C001",
      expiry: "2026-07-29",
      openedAt: null,
      notes: "",
      archived: false,
      createdAt: "2026-06-08T10:00:00Z",
      status: "ready"
    }
  ],
  settings: {
    alertDays: 30
  }
}
```

## 7. 상태 정의

### 7.1 상태 목록

- `ready`: 미개봉
- `in_use`: 사용중
- `warning`: 곧만료
- `expired`: 만료
- `archived`: 폐기

### 7.2 상태 판정 규칙

1. `archived = true` 이면 `archived`
2. `openedAt`가 있으면 `in_use` 또는 `warning` 또는 `expired`
3. `openedAt`이 없으면 `ready` 또는 `warning` 또는 `expired`
4. 실효 종료일이 오늘보다 이전이면 `expired`
5. 실효 종료일까지 `alertDays` 이하로 남으면 `warning`

## 8. 날짜 계산 규칙

### 8.1 사용기간 종료일

```text
openedAt + wearDays
```

### 8.2 실효 종료일

```text
실효 종료일 = min(유효기간, 사용기간 종료일)
```

개봉하지 않은 재고는 실효 종료일을 유효기간으로 본다.

### 8.3 우선 사용 순서

정렬 기준은 아래 순서로 적용한다.

1. 실효 종료일이 빠른 항목
2. 사용중 항목 우선
3. 개봉일이 빠른 항목
4. 등록일이 빠른 항목

## 9. 알림 규칙

기본 알림 기준은 `alertDays = 30`이다.

### 경고 단계
- 30일 전
- 14일 전
- 7일 전
- 3일 전
- 1일 전
- 당일
- 만료 후

### 표시 방식
- `warning`: 주황색 계열
- `expired`: 빨간색 계열
- `archived`: 회색 계열
- `ready`: 파란색 계열
- `in_use`: 초록색 계열

## 10. 사용 흐름

### 10.1 입고
1. 센서 종류 선택
2. LOT 입력
3. 유효기간 입력
4. 저장

### 10.2 사용 시작
1. 재고 선택
2. 개봉일 입력
3. 상태를 `in_use`로 전환

### 10.3 사용 종료
1. 재고 선택
2. 사용 종료 처리
3. 상태를 종료 상태로 반영

### 10.4 폐기
1. 재고 선택
2. 폐기 처리
3. 목록에서 별도 구분

## 11. 센서 종류 관리

센서 종류는 고정값처럼 쓰지만, 설정 화면에서 추가/수정이 가능해야 한다.

### 항목
- 이름
- 사용기간
- 색상
- GTIN
- 모델명

### 주의점
- 종류 이름은 사용자 표시용이다.
- 실제 판정은 `id`를 기준으로 한다.
- GTIN이 있으면 등록 시 자동 매칭에 활용할 수 있다.

## 12. 검증 규칙

### 재고 등록 검증
- 센서 종류 필수
- 유효기간 필수
- 유효기간은 오늘 이전만 아니면 허용
- 개봉일은 유효기간보다 늦지 않게 입력하는 것을 권장

### 수정 검증
- 사용중 재고의 개봉일 변경 시 실효 종료일을 재계산한다.
- 폐기된 항목은 다시 사용중으로 돌릴 수 있게 할지 정책을 정해야 한다.

## 13. 예외 처리

- 유효기간이 누락된 재고는 경고 대상으로 표시하지 않고 입력 오류로 본다.
- 개봉일이 없는데 사용중 상태면 보정하거나 저장을 막는다.
- 실효 종료일 계산이 불가능하면 상세 화면에서 오류 메시지를 보여준다.

## 14. 백업 / 복원

### 백업
- 현재 localStorage 데이터를 JSON으로 내보낸다.

### 복원
- JSON 파일을 불러와 localStorage에 반영한다.

### 권장 방식
- 백업 파일에는 `sensorTypes`, `inventory`, `settings`, `version`을 포함한다.

## 15. 구현 우선순위

1. 데이터 구조 정의
2. 날짜 계산 함수 구현
3. 상태 판정 함수 구현
4. 재고 등록/수정 화면
5. 목록 및 상세 화면
6. 대시보드 요약
7. 설정 및 백업/복원

## 16. 완료 기준

아래가 만족되면 1차 기능은 완료로 본다.

- 센서 종류별 재고를 등록할 수 있다.
- 개봉일과 유효기간을 함께 계산할 수 있다.
- 만료 임박 순으로 재고를 보여줄 수 있다.
- 상태별 필터가 동작한다.
- 백업과 복원이 된다.
